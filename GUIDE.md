# 777 / sevenclient source guide

This guide describes the **source as uploaded** to `SINISTERCLIENT333`. The repository contains decompiled contents of a Fabric mod JAR. It is not a ready-to-build Gradle project. No original source file was changed for this guide. Read [REPORT.md](REPORT.md) for defects, risks, and review limits.

## Identity and repository layout

- The repository name is `SINISTERCLIENT333`; the code calls itself **777**, uses the Fabric mod id `sevenclient`, and puts its Java packages under `dev.sevenclient`. Keep these names distinct when looking up files or settings.
- [fabric.mod.json](fabric.mod.json) declares a client-side Fabric entry point, `dev.sevenclient.SevenClient`, version `1.7.0`, Java `>=21`, Fabric API, and Minecraft `~1.21`. The [manifest](META-INF/MANIFEST.MF) identifies the uploaded build as Minecraft **1.21.11**, Fabric Loader **0.19.5**, and the **intermediary** mapping namespace. The manifest is evidence about that JAR, not proof that every 1.21.x release works.
- `dev/sevenclient/` contains the decompiled Java files. `assets/sevenclient/font/` contains font files and font definitions. `fabric.mod.json` and `sevenclient.mixins.json` are at the root because the layout mirrors JAR contents. Most Minecraft types and members retain names such as `class_310` and `field_1724`, rather than human-readable mapped source names.
- There is no Gradle build definition, Gradle wrapper, normal `src/main/java` / `src/main/resources` tree, or test suite in the uploaded repository. **Do not treat this checkout as a directly reproducible source build or a compiled release.** The metadata declares `MIT`, but no license text is present in the uploaded tree; verify provenance and permissions before redistribution.

## Runtime flow

[SevenClient.java](dev/sevenclient/SevenClient.java) creates the friend/enemy stores, then `ModuleManager`, then `ConfigManager`, and loads the config. It registers `START_CLIENT_TICK` for bind polling and module `onTick`, `END_CLIENT_TICK` for `onPostTick`, and `HudRenderCallback` for `onHudRender`. Tick callbacks require a player and world. The HUD callback does not impose that guard itself.

[ModuleManager.java](dev/sevenclient/module/ModuleManager.java) instantiates 23 modules in a fixed order. It calls only enabled modules. Each tick, post-tick, frame, HUD, and attack dispatch catches failures from each module separately, logs an error, and disables that module. Module keybinds support toggle or hold behavior and are not polled for a new toggle while a screen is open. Already-enabled module callbacks can still run while a screen is open; individual modules must apply their own screen checks.

[MouseMixin.java](dev/sevenclient/mixin/MouseMixin.java) calls [FrameDispatcher.java](dev/sevenclient/util/FrameDispatcher.java) from a mouse-update hook. If that source has not run for five HUD frames, the HUD render callback supplies a fallback. Frame deltas come from `System.nanoTime()` and are clamped to **0.001–0.1 seconds** before `ModuleManager.onFrame(dt)`. The dispatcher checks for a player, world, and client instance; it does not check whether a GUI is open. This path matters for aim smoothing and other per-frame behavior.

[ClientPlayerInteractionManagerMixin.java](dev/sevenclient/mixin/ClientPlayerInteractionManagerMixin.java) feeds the module attack callback. Other mixins hook movement packet rotation, interaction-time rotation, velocity, connection send, camera, outlines, mouse scroll, and settings access. The set of registered hooks is in [sevenclient.mixins.json](sevenclient.mixins.json). Some injections use `require = 0`, so the absence of a mixin error is not proof that a hook executed; check the telemetry.

## Settings and state

[Module.java](dev/sevenclient/module/Module.java) owns a module's name, category, enabled flag, keybind mode, and registered settings. Setting types are `BoolSetting`, `NumberSetting`, `ModeSetting`, `StringSetting`, and `KeySetting` under [`module/setting/`](dev/sevenclient/module/setting/). `reg(...)` puts a setting in the list used by the GUI and config; `visibleWhen(...)` controls when a setting is shown. Numbers are bounded and snapped to their setting step.

[ConfigManager.java](dev/sevenclient/config/ConfigManager.java) stores `module.setting=value` lines at Fabric's config directory under `777client/config.txt`. It loads once at initialization. The format is not escaped: manually editing values with newlines can damage parsing. `Module.enabled` is written before that module's settings and loaded in file order, so `onEnable` can run before saved setting values are applied. Config is saved when [ClickGuiScreen.java](dev/sevenclient/ui/ClickGuiScreen.java) closes and at JVM shutdown; it is **not** continuously saved on every setting change. Friend and enemy name stores in [FriendManager.java](dev/sevenclient/util/FriendManager.java) and [EnemyManager.java](dev/sevenclient/util/EnemyManager.java) are separate runtime data structures. Do not assume config persists their contents without confirming an explicit save path.

The UI entry point is [ClickGuiModule.java](dev/sevenclient/module/impl/ClickGuiModule.java). Its default key is Right Shift (GLFW code 344). It acts like a one-shot command: enabling opens the GUI and immediately marks the module disabled again.

## Aim, target selection, and rotation

### Targets and aim engines

[TargetUtil.java](dev/sevenclient/util/TargetUtil.java) scans eligible living entities and minimizes a score of **distance + 0.045 × angular error** for its general selector. Its nearest-point helper clamps the player's eye coordinates into the target bounding box. [TargetScores.java](dev/sevenclient/util/TargetScores.java) offers a yaw-only selection mode, which ignores pitch in the target-ranking step.

[AimAssist.java](dev/sevenclient/module/impl/AimAssist.java) is the older view-rotation assist. The inspected movement path uses [AimSolver.java](dev/sevenclient/util/AimSolver.java), a second-order error/velocity controller whose movement time is based on Fitts's-law-style `a + b × log2(2D/W + 1)` with a width floor. [SmoothNoise.java](dev/sevenclient/util/SmoothNoise.java) supplies multi-octave noise. [TurnLatch.java](dev/sevenclient/util/TurnLatch.java) can latch a turn direction on a large angle change. `Human` supplies a session-level timing profile. Some later functions in this large decompiled file were **not** fully retrievable for this review; the full activation path is not certified here.

[AimAssist2.java](dev/sevenclient/module/impl/AimAssist2.java) is a separate assist; it yields when the older AimAssist is enabled. It can select by general score or yaw, checks weapon/block-break/mouse requirements, retains a target while it passes `stillValid`, applies a max-angle gate, then delegates to [AdaptiveAim.java](dev/sevenclient/util/AdaptiveAim.java) or [SimpleAim.java](dev/sevenclient/util/SimpleAim.java). `SimpleAim` tracks yaw/pitch error with velocity buffers, close-range shaping and occasional drift. In the **retrieved first portion** of `AdaptiveAim`, a bounded frame delta and smoothing of target points/lead are visible, plus subtraction of the engine's own last movement to estimate external mouse input. The second portion, including final motion output and `strength()`/`isYielding()`, could not be read in full. Do not infer its complete mathematical behavior from field names alone.

[HitFlick.java](dev/sevenclient/module/impl/HitFlick.java) uses a short flick-and-return state machine and [MouseRotation.java](dev/sevenclient/util/MouseRotation.java) to move actual player yaw in discrete mouse-count steps. It does **not** submit a request to the shared silent-rotation priority system.

### Shared rotation paths

[Rotations.java](dev/sevenclient/util/Rotations.java) wraps yaw differences, clamps pitch, and computes the live mouse-sensitivity degree step: `gcd = (sensitivity × 0.6 + 0.2)^3 × 8 × 0.15`. `MouseRotation` independently calculates the same step and applies integral mouse-count updates with fractional carry. [RotationSync.java](dev/sevenclient/util/RotationSync.java) uses that step to round deltas from its last-sent yaw/pitch at packet or interaction boundaries. This code is sensitive to hook order and to which routine last changed the actual player rotation.

[SilentAim.java](dev/sevenclient/module/impl/SilentAim.java) offers **Camera**, **Glide**, and **Packet** modes. Camera/Glide call `RotationSync.applyHidden`: despite the name, this **changes real player yaw/pitch**; [CameraMixin.java](dev/sevenclient/mixin/CameraMixin.java) subtracts a bounded hidden offset only during camera update so the local view follows less of that motion. It does **not** make Camera/Glide rotations invisible to the server. Packet mode requests a per-tick rotation and [ClientPlayerEntityMixin.java](dev/sevenclient/mixin/ClientPlayerEntityMixin.java) temporarily applies it around the movement-packet send, then restores the previous rotation. Packet mode is the one that uses `RotationSync` ownership/priority arbitration. The candidate-angle `raycastHits` routine checks an entity bounding-box intersection; it does **not** trace blocks or prove line of sight through a wall.

## Reference, limits, and safe checks

The supplied [RSSeeker/Vape-v4](https://github.com/RSSeeker/Vape-v4) repo describes itself in its [English README](https://github.com/RSSeeker/Vape-v4/blob/main/README_EN.md) as an independent recovery/research project with a Java layer and Windows x64 native bridge, **not official Vape source**. Its injection and build model differs from this Fabric mod's client entry point and mixins. It is useful as architecture context, not a verified performance, behavior, or detection benchmark. No code was copied from it.

This was a **static source review**. The uploaded source was not compiled or run, no server behavior was measured, and the full tail of two >30 KB aim files could not be retrieved through the available file-content response. See [REPORT.md](REPORT.md) for what is confirmed, what is inferred, and a suggested order of validation. Keep original source files intact if reproducing this review.
